# Case GC – AGES PUCRS

## AGES
- Agência Experimental Eng. Software
- Ambiente prático, simulação mercado
- Projetos reais, cliente, gestão, dev
- 4 níveis (I–IV), sequenciais

## Níveis
- I -> protótipo, desenvolvimento
- II -> modelagem BD, artefatos, ajuda I
- III -> arquitetura, bootstrap, CI/CD, padrões, ajuda I+II
- IV -> gerente, cliente, requisitos, tarefas, retros

## Ferramentas
- GitLab Wiki -> docs
- Trello -> tarefas/requisitos
- README, outros -> guias
- Reuniões ágeis (planning, retro)

## SECI (Nonaka & Takeuchi, 1995)

Socialização (tácito -> tácito)
- Troca entre níveis
- Mentoria natural
- Trabalho lado a lado

Externalização (tácito -> explícito)
- Wiki registra práticas
- Retros -> action items
- Trello -> requisitos

Combinação (explícito -> explícito)
- Requisitos + BD -> especificação
- CI/CD + Wiki + padrões
- Reuso docs/códigos

Internalização (explícito -> tácito)
- I aprende padrões do III
- II aplica lições retro
- IV internaliza liderança

## Síntese
- GC garante continuidade, memória organizacional 
- Artefatos -> não perder conhecimento
- SECI fecha ciclo entre turmas
